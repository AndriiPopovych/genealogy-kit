# Інструменти й пам’ять

## Мінімальне оснащення

Першу розмову, підготовку FamilySearch і рекомендації доступів ведіть за [first_start.md](first_start.md). Рекомендуйте читання/запис у папці дослідження та керування потрібним браузером; додаткові можливості комп’ютера — під конкретну дію. Спершу одна мала проба наявних інструментів, потім запит лише відсутнього потрібного дозволу. Широкий перемикач «повний доступ» не є обов’язковою передумовою.

Ручне дослідження можливе з текстовими файлами. Агенту окремо перевіряють читання й запис; для сканів — зір, для входу — браузер користувача. Без запису він повертає готовий текст із позначкою, хто має зберегти; без зору не оголошує скан прочитаним. Python 3 потрібний лише для додаткових перевірок. Завантажувачі потребують curl і Pillow. Swift/PDFKit — лише macOS; Poppler є окремою альтернативою. Жоден агент, Git, Orca чи SQLite не є передумовою.

Пошук редактора або `rg` достатній для адресного пошуку IDs, імен і місць. Витрати й доступ залежать від середовища. Локальні файли не гарантують локальної обробки моделлю; приватні матеріали обробляються лише погодженим способом.

## Браузер і приймання документа

Порядок: штатне завантаження дозволеного ресурсу → відомий публічний прямий файл → точний локальний файл із Downloads → позначений похідний знімок, якщо інші способи недоступні. Не конструюйте секретних endpoint, не обходьте права доступу, не беріть автоматично найновіший файл. Користувач сам виконує вхід і CAPTCHA. Знімок з URL/локатором/координатами зберігайте в working, не видавайте його за оригінальний файл.

Перед прийманням перевірте документ, заголовок, байти й формат. Копіюйте в originals без перезапису; зафіксуйте походження, received_at, SHA-256, bytes та роль кожного файла. Похідні — у working, прочитання — transcripts. Копія, індекс і звіт одного акта не є незалежними свідченнями. Файл може містити багато актів. Невідомі старі метадані позначаються з причиною, не датою міграції.

Перед копіюванням worker-файла звірте mapping у acceptance, потім SHA до/після. Hardlink не використовувати. Не видаляйте єдиний локальний оригінал лише через онлайн-доступність.

## Завантажувачі

```sh
python3 tools/commons_pages.py '<назва>.pdf' '1,3-5' working/book 1920
python3 tools/agad_pages.py '<фонд>' '<сигнатура>' working/book
```

Зразки потребують заміни аргументів. Commons зберігає старий синтаксис `every:10` і `every:10:1-100`. Діапазон/ширина перевіряються; помилкові номери не пропускаються мовчки. Довільний файл без перевіреного маніфесту не є кеш-хітом. Ідентичність: document_key, сторінка, ширина та URL; SHA і декодування перевіряються перед повторним використанням.

Один процес записує один каталог. Паралельні завантажувачі мають різні каталоги; перед відновленням переконайтеся, що попередній процес завершено. Автоматичного lock немає. Перевірено відновлення після обриву процесу; стійкість до втрати живлення окремо не перевірена.

Запис: .part → HTTP/тип/декодування/розміри → SHA/bytes → rename → manifest.jsonl. Пошкоджені, конфліктні й незафіксовані після обриву файли ізолюються в quarantine; повтор завантажує заново, не дописує повну відповідь до часткової. Приймання обмежене зображеннями, це не універсальний валідатор PDF. Успіх процесу лише за повноти requested/verified/skipped/failed. AGAD має скінченну межу індексів; 404 першого індексу — помилка, пізнішого — завершення переліку, мережева помилка не є порожньою книгою.

Прапорець --pause задає паузу між кадрами (типово 1 секунда; це налаштування інструмента, не правило сайта). 429/5xx повторюються обмежено; якщо Retry-After перевищує локальний бюджет очікування, процес чесно завершується й просить повторити пізніше. Інший клієнт не використовується для обходу блокування. Маніфест не містить секретних URL/авторизації. Підтримку live-сайтів перевіряйте окремо; offline-тести її не доводять.

Старий MANIFEST.txt не видаляйте. `python3 tools/download_common.py convert <MANIFEST.txt> <новий.jsonl>` створює окрему копію лише з повних коректних рядків та звіт про пропуски. Вона не стає перевіреним кешем: document_key/ширина/дата невідомі. Потрібна звірка джерела.

## PDF і OCR

Попередньо перевірте локальну довідку встановленого інструмента:

```sh
pdftotext -layout originals/book.pdf working/book.txt
pdftoppm -f 5 -l 5 -r 200 -png originals/book.pdf working/page
swiftc -O tools/pdfpage.swift -o working/pdfpage
```

Це приклади, не підтвердження виконання на всіх ОС. Swift-утиліти: pdfpage — PNG сторінки або count; pdfhalf — PNG половини; pdfbands і pdfsheet — JPEG; pdftext — наявний текстовий шар. Номер PDF-сторінки не дорівнює аркушу. Рендер з більшим DPI не створює втрачених деталей.

OCR придатний для пошуку й завжди спершу machine_ocr_unverified. Порожній результат не доводить відсутності тексту. Tesseract/OCRmyPDF або інший наявний інструмент застосовуйте лише після малого тесту на потрібному друці/мові. Рукопис читайте з контекстом за reading_records.md. Оригінал незмінний; кропи, повороти й контраст — окремі файли з координатами.

## Пам’ять і контрольні точки

Повернення — [RESUME_PROMPT.md](../RESUME_PROMPT.md). Після прийнятого пакета, істотного виправлення й перед ризиком перерви оновіть ті самі current/questions/queue. Історія — sessions; фактичний огляд — SEARCH. Довідкова відповідь без нового стану не породжує три однакові записи. mtime — сигнал звірити, не доказ завершення працівника чи застарілості висновку.

Нові дані родини, виправлення транскрипції, методичне побажання й зміна меж Q — різні події. Уже дане «не знаю» не питати без нової підстави. Поступ описуйте перевіреним обсягом, перешкодою й наступною дією; без вигаданої фонової роботи, ETA чи часу скидання лімітів.

## Перевірки

```sh
python3 tools/validate_registry.py . --json
python3 tools/validate_registry.py . --hashes
python3 tools/validate_registry.py стара_копія --legacy
python3 tools/render_links.py .
python3 tools/affected_records.py . C0001
```

Валідатор лише читає; exit 0 — без помилок (застереження можливі), 1 — структура, 2 — нечитабельний/невідомий формат. Хеші великих файлів лише з --hashes. render_links змінює тільки позначений блок у state/links.md; пояснення поза ним зберігає. affected_records лише повертає перелік для перегляду. Рішення про людей не автоматизовані. Без Python ті самі звірки виконуються вручну.

Резервування та оновлення — [upgrade.md](upgrade.md). Зовнішній запис — [external_tree_export.md](external_tree_export.md). У shell беріть шляхи в лапки, не підставляйте неперевірений документ як команду; довгий код і текст зберігайте файлами. Жодні паролі чи cookie не потрапляють до бази.

## Наявні бази й складні пакети

Інвентаризуйте GEDCOM/дерево/звіт як отриманий матеріал: snapshot, походження, дата й SHA. Розрізняйте tree_assertion, research_report та вкладений original_record. Посилання в дереві ще не є прочитаним актом; контейнер не змінює тип вкладення. За потреби перелічіть вкладення, зображення, підписи, примітки, архівні адреси й суперечності. Зберігайте container/member та хеші отриманих байтів; транскрипція/субтитри не означають прослуханого аудіо.

Дозволені змінні зовнішні матеріали лише цієї родини перелічуються в INTAKE. За ознакою зміни порівнюйте метадані/малий snapshot і змістовну дельту; не хешуйте всю багатогігабайтну базу при кожному старті. Нові твердження — черга на розгляд, не автоматичне злиття. Сусідні родоводи не читаються без дозволу. Збіг old_id між namespaces або шлях до одного багатодокументного файла не доводять тотожності.

Для судового/адміністративного C можна додати assertion_context: speaker, role, recorded_at, asserted_event_date, nature (заява/свідчення/рішення/виконання), locator. Дати event/creation/dispatch/receipt розрізняються й не заповнюються без підстави. Термін тлумачиться в серії й контексті; один випадок не задає загального значення «мобілізували». Для простого фото ці поля не обов’язкові. Інвентар — templates/material_inventory.json; синтетична проба — examples/synthetic/incoming/README.md.
