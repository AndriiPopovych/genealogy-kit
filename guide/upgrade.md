# Оновлення без втрати дослідження

VERSION — версія комплекту; data/format.json.schema_version — версія даних. Відсутній marker означає legacy, не найновіший формат. KIT_FILES.json описує дистрибутив, але не дозволяє перезаписати локальні файли. Автооновлювача немає; Git необов’язковий.

1. Зробіть повну копію старої папки в іншому місці, з інвентарем відносних шляхів, bytes і SHA-256. Перевірте копію за хешами. Встановіть базову версію, локальні правила, відкриті Q й задачі; невідома версія допустима.
2. Порівняйте лише потрібні guide/tools/templates/prompts. Не замінюйте INTAKE/data/state/originals/transcripts та локальні доповнення AGENTS/CLAUDE. Побажання можна перенести в INTAKE лише з видимим diff; первісний текст лишається в backup.
3. Запустіть --legacy (або ручну діагностику), складіть dry-run old/new без запису. Невідомі поля й старі enum лишаються; висячі посилання, дублікати та битий JSON не маскуються.
4. На окремій повній робочій копії змінюйте тільки відомі структури за [контрактом](../templates/records.md). Зберігайте старі IDs, namespaces, aliases, сирі свідчення, приблизні дати, локатори, шляхи й усі JSONL-рядки. Невідомі дати не підміняйте сьогоднішньою. Імпорт іншої системи потребує таблиці `(source_namespace, old_id) → new_id`, не злиття за old_id чи файлом.
5. Запишіть журнал застосування: old/new, причина/доказ, дата, автор. Завершений CHANGE незмінний; у pending допускається лише applied після фактичного застосування. Статуси спорідненості не мігрують автоматично. Старий reviewed без метаданих — застереження; спершу шукайте наявну транскрипцію, не вимагайте масового перечитання.
6. Перевірте кількості й кожний старий ID/текст/рядок журналу, локальні файли/хеші, посилання, чинний Q та продовження. Повтор на тій самій копії не додає записів. Змоделюйте відкат поверненням з backup і порівняйте всі хеші.
7. Лише після звірки переключіть робочу папку на нову копію. Стару зберігайте доступною. Кілька файлових змін не називаються атомарними через один rename.

Невідомий формат зупиняє лише його міграцію, а не читання джерел та незалежну роботу. Не ставте schema_version=1, поки не виконана сувора перевірка. Успішний JSON parse не доводить збереження змісту.
