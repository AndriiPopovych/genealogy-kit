# Чистий локальний пакет

Код розвивається в одному Git-репозиторії; випуски позначаються тегами. Папки з копіями кожної версії в репозиторії не ведемо. Ця процедура потрібна для перевірки складу та необов’язкового ZIP до GitHub Release з відповідного тегу. Усі команди виконуються з кореня комплекту; для дослідження родини Git не потрібний.

Власник обрав [MIT](../LICENSE) для комплекту; [межі застосування](../LICENSE_STATUS.md) описано окремо. Ця процедура готує локальну перевірювану копію й нічого не публікує. LICENSE має входити до явного переліку файлів; інвентар бере ліцензію з KIT_FILES.json.

KIT_FILES.json — явний перелік дозволених вихідних файлів, їхніх SHA-256, типів і цільових шляхів. Для приватних стартових даних беруться тільки перевірені templates/starter, а не робочі INTAKE/data/state. Дозволено інструкції, guide, templates, tools, тести та повністю синтетичні examples. Перелік змінюється лише після редакційної перевірки. Сам KIT_FILES не хешує себе; його SHA міститься в окремому інвентарі готового архіву.

```sh
python3 tools/build_release.py . dist/kit
```

Призначення має не існувати. Пакувальник перевіряє SHA, забороняє symlink і виходи за корінь, складає нову папку й ZIP, перечитує фактичний архів, порівнює імена/байти й створює інвентар. Порожні робочі каталоги створюються з окремого списку. .gitignore є лише допоміжним бар’єром.

dist/ містить лише згенерований результат і виключено з Git. Для повторної збірки використай нову тимчасову папку або прибери попередній результат після перевірки, що в ньому немає ручних змін. Не зберігай у dist/ єдині копії важливих матеріалів. Перед тегом узгодь VERSION, CHANGELOG та KIT_FILES.json за CONTRIBUTING.md; сама збірка нічого не комітить і не публікує.

Не включати proposals/reviews, заповнені INTAKE/data/state, workers, originals/transcripts/working/inbox/exports/drafts, логи, backups, браузерні профілі й акаунтні налаштування. Перевіряйте також текст дозволених інструкцій — allowlist не очищує приватний текст всередині дозволеного файла.

Перед передаванням огляньте весь ZIP та інвентар, виконайте canary-тест на окремій копії й перевірте порожні реєстри та наявність LICENSE. Для нових сторонніх матеріалів перевіряйте їхні власні права й умови. Live-сайти, інші ОС та всі агенти не оголошуються підтриманими за локальними тестами.
