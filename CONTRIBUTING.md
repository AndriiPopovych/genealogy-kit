# Розробка genealogy-kit

Поточна папка є коренем вихідного коду комплекту та його Git-репозиторію після підключення Git. У локальному робочому просторі вона може називатися public; на GitHub її вміст лежить безпосередньо в корені репозиторію. Поліпшення робимо тут.

## Робочий процес

Мова інструкцій і звітів — українська; текст MIT зберігається англійською. Зберігай три окремі оцінки, можливість аргументованих accepted_working і межу між структурною перевіркою та генеалогічним рішенням з [AGENTS.md](AGENTS.md).

Перед редагуванням наявних файлів зберігай резервні копії та SHA-256 поза публічним репозиторієм. Огляди, робочі звіти та приватні матеріали також зберігай зовні. Приклади й тестові матеріали мають бути повністю синтетичними.

INTAKE/data/state у корені — порожній стартовий комплект. Канонічні стартові шаблони лежать у templates/starter; після зміни шаблону узгоджуй відповідний порожній файл у корені. Реальні родинні дані записуй лише в окрему копію для дослідження. `.gitignore` не захищає вже відстежувані файли від потрапляння змін у коміт.

## Перевірки

Запускай з кореня комплекту перевірки, доречні до зміни. Повний набір:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

Для HTTP-тестів потрібні curl, Pillow і доступ до loopback; вони не звертаються до реальних архівних сайтів. Swift/PDFKit перевіряється лише на macOS зі swiftc. Без потрібних можливостей назви неперевірений обсяг, не заявляй універсальної підтримки. Залежності завантажувачів описані в tools/requirements-downloads.txt.

Для тестів PDF-генератора додатково потрібні tools/requirements-reports.txt і локальний TTF із кирилицею; за потреби задайте KIT_TEST_FONT. Без них PDF-тести позначаються skipped. Сценарії поведінки агента описані в examples/synthetic/research-control-scenarios.md; unit-тести не доводять їх виконання реальним агентом.

Структурні перевірки:

```sh
python3 tools/validate_registry.py .
python3 tools/validate_registry.py examples/synthetic --hashes
```

Перевір склад Git перед публікацією: синтетичні originals/transcripts/exports усередині examples мають потрапляти до репозиторію. Приватні каталоги виключаються `.gitignore` тільки від кореня комплекту.

## Версії та випуски

Розробку ведемо комітами, готові стани позначаємо тегами. Перед тегом онови VERSION, CHANGELOG та версію KIT_FILES.json, перевір його дозволений склад і SHA-256 змінених файлів. Історію випусків не дублюємо папками з повними копіями коду.

Для перевірки чистого пакета або ZIP як додатка до GitHub Release використай [guide/release.md](guide/release.md). Згенеровані dist/ і ZIP не коміть. GitHub Release пов’язується з відповідним тегом; завантаження й публікація потребують вказівки власника. Git не потрібний користувачу для самого генеалогічного дослідження.
